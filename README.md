# 🪑 Консольное приложение: Учёт реставрации мебели

Индивидуальный итоговый проект по курсу «Python и основы CS».  
Приложение предназначено для автоматизации учета выполненных работ по реставрации мебели, контроля затраченных материалов, формирования отчётов и хранения истории заказов.

---

## 📌 Назначение программы
Программа решает бизнес-задачу учета в реставрационной мастерской:
- Ведение базы данных отреставрированных предметов и выполненных заказов.
- Быстрое изменение и добавление новых данных без перезаписи всего файла.
- Анализ объёмов выполненных работ через встроенный поиск и сортировку.
- Потоковая обработка отчётов без перегрузки оперативной памяти.
- Сохранение текущего состояния в формат `JSON` и загрузка данных из `CSV`.

## 🛠 Выполнение обязательных требований курсового проекта

### 1. Данные и алгоритмы
- **`list`**: используется для сохранения порядка добавления элементов (`self.items`).
- **`dict`**: используется для мгновенной индексации и поиска записей по ключу (`self.item_index_map`).
- **`set`**: применяется для хранения уникальных категорий мебели (`self.categories`).
- **Собственный поиск**: реализован линейный поиск $O(N)$ по подстроке наименования мебели без применения встроенных методов фильтрации.
- **Собственная сортировка**: алгоритм Bubble Sort (сортировка пузырьком) со сложностью $O(N^2)$ для упорядочивания по количеству или стоимости.

### 2. ООП и Архитектура
- **Композиция**: класс `RestorationOrder` включает объекты классов `FurnitureItem` и `Material`.
- **Защита данных (`property`)**: закрытые поля с проверочной логикой на неотрицательные значения стоимости и количества (генерирует `InvalidValueError`).
- **Полиморфизм**: общий метод `get_info()` из абстрактного базового класса `Describable`, переопределенный для всех моделей.
- **Dataclass**: базовые сущности объявлены через декоратор `@dataclass`.

### 3. Поток данных и файлы
- **`CSV`**: импорт исходных данных через стандартный модуль `csv`.
- **`JSON`**: сохранение результатов и выгрузка отчётов через модуль `json`.
- **Генератор**: метод `lazy_load_report()` реализует ленивую (потоковую) выдачу записей `yield` без полной загрузки набора данных в память.

### 4. Устойчивость и надёжность
- **Кастомные исключения**: `RestorationError` и `InvalidValueError` для обработки бизнес-ошибок.
- **Логирование**: все ключевые операции и ошибки записываются в файл `app.log` через модуль `logging`.
- **Type Hints**: публичные методы и функции снабжены аннотациями типов.
